Шпора по командам в Линухах.  

1. Повседневные - навигация, работа с файлами, ввод/вывод.  

pwd  
// Где мы.  
// Показывает полный путь текущего рабочего каталога.  

whoami  
// Кто мы. Показывает под кем мы зашли.  

ls  
// Содержимое каталога.  
// Часто используется с комбинацией флагов -lah для показа скрытых файлов  
// и вывода подробной инфы (размеров, прав, дат).  

cd  
// Смена каталога.  
// cd - возврат в предыдущую директорию.  
// cd.. - на один уровень наверх.  
// cd ~ - сразу в домашний каталог.  

mkdir  
// Создать папку.  
// Флаг -p создаёт вложенную подпапку, например mkdir -p dir/subdir  

touch  
// Создать пустой файл.  
// Обычно используется для создания конфигов с нуля.  
// Примеры:  
// touch example.txt  
// touch config.cfg  

cp  
// Копирование файлов и папок.  
// cp file.txt /tmp/ - копируем файл file.txt в каталог /tmp/  
// Флаг -r нужен для рекурсивного копирования директорий.  
// Флаг -i спросит подтверждение при перезаписи существующего файла.  

mv  
// Перемещение или переименование.  
// Пример: mv old_name.txt new_name.txt - переименует файл.  
// Пример: mv /path/dir/* ./ - переместит все файлы из /path/dir в текущий каталог.  
// С флагом -i команда запросит подтверждение перед перезаписью файлов при перемещении.  

rm  
// Удаление файлов или папок.  
// Пример: rm file.txt - удаление файла.  
// Для удаления папки и всего её содержимого используется рекурсивный  
// флаг: rm -r folder (осторожно! Файлы удаляются безвозвратно!)  
// Флаг -f принудительно удалит всё без запроса.  
// Флаг -i с запросом подтверждения.  

cat  
// Посмотреть содержимое файла прямо в терминале.  
// Отредактировать не даст, даст только посмотреть.  

head или tail  
// Показывают начало или конец вывода файла. По умолчанию 10 строк.  
// Пример: head -n 5 large.log - выведет первые 5 строк файла.  
// Пример: tail -n 5 large.log - выведет последние 5 строк файла.  
// Пример: tail -f large.log - будет постоянно следить за появлением новых строк в конце лога.  
// Её часто используют для просмотра логов в реальном времени. Чтобы остановить - жмём Ctrl + C.  

Переадресация ввода/вывода  
// > - перезаписывает вывод команды в файл.  
// >> - дописывает что-то в конец файла.  
// < - берёт ввод из файла.  
// | - перенаправляет вывод одной команды на ввод другой.  
// Пример: ls /etc | grep conf > conf_files.txt - результат ls фильтруется по слову "conf"  
// и сохраняется в файл.  

less  
// Постраничный просмотр текста.  
// Позволяет прокручивать длинный вывод вверх/вниз клавишами PgUp и PgDdn или стрелками.  
// Пример: ls -l /bin | less - листать длинный список файлов. Для выхода: Q

2. Работа с сетью.  

ping  
// Проверка доступности узла в сети. Отправляет ICMP эхо-запросы и измеряем время отклика.  
// Пример: ping -c 4 8.8.8.8 - посылает 4 пакета на адрес 8.8.8.8  
// Пример: ping -t 8.8.8. - бесконечный пинг на адрес 8.8.8.8  

traceroute / tracert  
// Трассировка маршрута до узла. Список промежуточных узлов  
// Ключ -d - игнорит DNS-имена и прогоняет трассировку только по IP-шникам, что несколько быстрее и точнее.  

ifconfig / ip addr show / ip a  
// Показывает ip-адреса всех сетевых интерфейсов.  
// В современных системах чаще используется ip a  

ip route show  
// Покажет таблицу маршрутизации.  

netstat / ss  
// Отображает сетевые соединения и порты.  
// netstat -tulnp - перечисляет прослушиваемые TCP/UDP порты и соответствующие PID процессов.  
// Самого netstat-a, скорее всего, не будет, его надо будет установить путём выполнения команды:  
// sudo apt update  
// sudo apt install net-tools - это для Дебианов, Убунт, Минт и им подобных.  
// sudo dnf install net-tools - это для Центосов, Федор, РХЕЛОВ и прочего.  
// Но современный аналог net-tools - это ss -tulwnp (работает быстрее и установлен из коробки).  

curl  
// С помощью Курла можно получать данные о HTTP/HTTPS, FTP и т.д.  
// Также, можно скачивать файлы как обычной качалкой.  
// Пример: curl -l https://example.com - выведет заголовки ответа HTTP от example.com.  
// Чтобы загружать файлы используем ключ -O  

wget  
// Консольная файлокачалка по URL. Файл скачивается в текущий каталог.  
// Пример: wget https://wordpress.org/latest.zip - скачает файл latest.zip в текущий каталог.  

ssh  
// Подключение к удалённому серверу по протоколу SSH.  
// Пример: ssh user@host - просто подключиться по SSH.  
// Пример: ssh -p 2222 user@host - подключиться по меняному порту 2222  
// Пример: ssh -L 5432:localhost:5432 user@host - если на сервере PostgreSQL слушает 5432  
// и локальный клиент подключается к localhost:5432  
// Пример: ssh -R 8080:localhost:3000 user@host - то есть приложение, доступное у тебя на  
// localhost:3000, становится доступно через порт 8080 на сервере.  
// -L - открыть удалённый сервис локально!  
// -R - открыть локальный сервис на удалённой стороне!  
// Ещё примеры!  
// ssh -L 9000:10.0.0.5:80 user@host  
// Означает мой localhost:9000 ---> SSH-сервер host ---> 10.0.0.5:80  
// ssh -R 9000:localhost:3000 user@host  
// Означает host:9000 ---> SSH-туннель ---> мой localhost:3000  

telnet / nc (netcat)  
// telnet - это менее безопасный аналог ssh. Не шифрует ничего.  
// Пример: telnet example.com 25 - попытка подключиться к example.com по 25 порту (SMTP).  
// Пример: nc -vz example.com 25 - проверит доступность порта с выводом результата.  

scp  
// Копирование файлов по ssh между хостами.  
// Пример: scp backup.tar user@remote:/backup/ - скопирует файл backup.tar  
// на удалённый сервер remote в каталог /backup/  

dig / nslookup  
// Утилиты для DNS-запросов.  
// Пример: dig example.com - покажет DNS-записи домена example.com  
// Пример: nslookup example.com - простой запрос DNS A-записи.  

hostname  
// Вывод, или изменение имени узла.  
// Если просто ввести hostname - покажет имя узла, если ввести hostname newsupername777 - переименует.

3. Управление файлами и файловой системой (копирование, монтирование, поиск).  

find  
// Поиск файлов и каталогов по заданным критериям.  
// Команда рекурсивно обходит указанную директорию.  
// Базовый синтаксис:  
// find [где искать] [условие]  
// find /home -name "test.txt" - искать test.txt внутри /home.  
// find . -name "test.txt" - искать test.txt внутри текущей директории.  
// find . -name "*.log" - найти все .log-файлы в текущей директории.  
// find . -name ".txt" - найти все файлы с расширением .txt в текущем каталоге и подкаталогах.  
// find . -type f - найти только файлы в текущей директории.  
// find . -type d - найти только директории в текущей директории.  
// find . -size +100M - найти файлы больше 100 МБ в текущей директории.  
// find . -mtime -1 - найти изменённые за последние 24 часа файлы в текущей директории.  
// Если добавить в конец -delete - удалит все найденные файлы.  
// Допустим, нужно найти все .log файлы больше 100 МБ:  
// find /var/log -type f -name "*.log" -size +100M  
// То есть find читается вот так:  
// [где искать] ---> [что искать] ---> [дополнительные условия] ---> [что сделать дальше]  

grep  
// Поиск совпадений в тексте файлов или выводе команд.  
// GREP - [G]lobal [R]egular [E]xpression [P]rint.  
// Ищет строки, совпадающие с шаблоном (поддерживаются регулярные выражения).  
// Пример: grep -R "ERROR" /var/log - рекурсивно найдёт строки с "ERROR" в файлах каталога /var/log  
// Флаг -i отключает чувствительность к регистру.  
// Флаг -n выводит номера строк.  
// Флаг -v инвертирует поиск.  
// ---> Поиск в одном файле.  
// grep -in "error" app.log  
// 15:Database ERROR  
// 42:connection Error  
// 87:CRITICAL error  
// ---> Поиск в нескольких файлах.  
// grep -in "error" *.log  
// app.log:15:Database ERROR  
// server.log:42:Connection Error  
// worker.log:87:Critical error  
// ---> Поиск во всей директории.  
// grep -rin "error" ./logs  
// -r - рекурсивный поиск во всех вложенных директориях.  
// -i - игнор регистра.  
// -n - показывать номера строк.  
// Что выведет?  
// ./logs/app.log:15:Database ERROR  
// ./logs/api/server.log:42:Connection Error  
// grep работает так:  
// grep -in [что ищем] [файл]  

locate  
// Мгновенный поиск файлов по имени через предварительно  
// проиндексированную базу.  
// Пример: locate *.pdf быстро найдёт все файлы  
// с расширением .pdf в системе.  
// Если у нас Ubuntu/Debian - устанавливаем так:  
// sudo apt install plocate  
// После установки база обычно обновляется автоматически.  
// Если надо вручную: sudo updatedb  
// И затем locate "*.pdf"  

tar  
// Консольный архиватор. Запаковка/распаковка файлов.  
// ---> Пример запаковки:  
// tar -czf archive.tar.gz /path/to/dir - создаст сжатый gzip-архив archive.tar.gz  
// из содержимого папки /path/to/dir.  
// ---> Пример распаковки:  
// tar -xvf archive.tar.gz - распакует архив в текущий каталог.  
// Основные флаги:  
// -c - создать,  
// -x - извлечь,  
// -z - сжать,  
// -v - подробный вывод,  
// -f <файл> - указываем имя архива.  

zip / unzip  
// Аналогичный консольный архиватор.  
// ---> Создать 1 ZIP-файл:  
// zip archive.zip file.txt  
// ---> Несколько файлов:  
// zip archive.zip file1.txt file2.txt  
// ---> Заархивировать папку и всё её содержимое:  
// zip -r archive.zip my_folder/  
// ---> Распаковать архив:  
// unzip archive.zip  
// ---> Распаковать в конкретную папку:  
// unzip archive.zip -d ./folder  
// ---> Удалить файл из ZIP  
// zip -d archive.zip file.txt  
// ---> Заархивировать с паролем:  
// zip -e archive.zip file.txt  

df  
// DF - [D]isk [F]ree.  
// Показывает свободное/занятое место.  
// Пример:  
// df -h - сводка по дискам в удобном для чтения формате (kb/mb/gb).  
// du - оценивает используемое пространство в каталогах или файлах.  
// Пример:  
// du -sh /var/log - показывает общий размер директории /var/log  
// du - размер занятого места,  
// -s - только итоговый размер,  
// -h - удобный формат (kb/mb/gb).  

mount  
// Монтирование файловой системы. Подключение раздела, диска,  
// или образа к каталогу. Используется для подключения устройств  
// (USB, диски) или сетевых ресурсов к общей файловой системе Linux.  
// Пример:  
// sudo mount /dev/sdb1/mnt/usb - здесь примонтируется /dev/sdb1 в каталог /mnt/usb.  
// После работы отмонтируем с помощью команды unmount /mnt/usb (отключение диска).  

lsblk  
// Отображает список блочных устройств - диски, разделы в виде дерева.  
// Полезно перед монтированием, чтобы узнать правильные имена устройств.  
// Пример:  
// lsblk -f - покажет устройства, их точки монтирования и файловые системы.  

fsck  
// Проверка и исправление файловой системы.  
// Пример:  
// sudo fsck -y /dev/sda2 - проверит раздел /dev/sda2 на ошибки и автоматически  
// попытается их исправить. -y автоматически отвечает "yes" на все вопросы.  
// Внимание! Запускать это только на отмонтированных или в режиме восстановления,  
// иначе может повредить смонтированную ФС.  

ln  
// Создание ссылок на файлы.  
// Примеры:  
// ln -s /path/to/file shortcut  
// shortcut - просто имя ссылки, расширение не нужно.  
// ln -s /var/log/app.log applog  
// applog - ссылка на /var/log/app.log

4. Процессы, мониторинг, системные службы.  

ps  
// Отображает запущенные в системе процессы (не интерактивно).  
// Примеры:  
// ps aux - выводит все процессы всех пользователей с подробностями (PID, UID, загрузка и т.д.).  
// Для подробностей можно использовать grep, например так:  
// ps aux | grep ngnix  

top / htop / btop  
// Динамический мониторинг процессов в реальном времени.  
// Обновляет список каждые несколько секунд. Показывает активные процессы, загрузку CPU, RAM и т.д.  
// Колонка PID - идентификатор процесса, USER - владелец процесса.  
// Внутри top нажимаем "H" для справки по хоткеям.  
// Например, P - сортировка по CPU, M - сортировка по RAM, Q - выход.  
// htop и btop более наглядный и красивый вывод. btop - самая последняя и красивая версия.  
// Чтобы установить htop и btop на Ubuntu и Debian:  
// sudo apt update  
// sudo apt install htop btop  
// На Fedora:  
// sudo dnf install htop btop  
// На Arch Linux:  
// sudo pacman -S htop btop  
// Устанавливать обычный top не нужно, он есть почти везде. Чтобы из них выйти: Q, F10, или Esc.  
// Запуск:  
// top  
// htop  
// btop  

free  
// Показывает объём свободной и используемой RAM.  
// Например: free -h - выведет статистику памяти в удобном формате (в гигах и мегабайтах).  
// Колонки: total, used, free, available и т.д.  

uptime  
// Общее время работы системы, или время с последней перезагрузки  
// + среднюю нагрузку (load average).  
// Пример:  
// 14:32:16 up 5 days, 3:21, 2 users, load average: 0.15, 0.10, 0.09  

kill  
// Посылает сигнал указанному процессу по PID.  
// Обычно используется для корректного завершения или принудительного прерывания процесса.  
// Пример: kill 1234  
// Посылает процессу с PID 1234 сигнал SIGTERM для завершения.  
// Если процесс не завершается, kill -9 1234 посылает SIGKILL (жёстское прерывание).  
// Перед -9 попробуйте мягкие сигналы или kill -15 (SIGTERM).  

pkill / killall  
// Завершение процессов по имени.  
// pkill name отправит сигнал всем процессам, чьё имя соответствует name (можно добавлять  
// -u user для процессов конкретного пользователя).  
// killall program то же самое.  
// Пример:  
// pkill -HUP nginx перезапустит все процессы nginx послав им сигнал HUP.  

nice / renice  
// Изменяет приоритет процесса.  
// nice -n 5 command запустит command с пониженным приоритетом (+5).  
// renice -n -10 -p 1234 повысит приоритет процесса с PID 1234 (более высокий приоритет =  
// более негативное значение nice).  

lsof  
// Выводит список файлов (и сокетов) процессов (list open files).  
// Пример:  
// lsof -i:80 - покажет процессы, слушающие порт 80, и связанные с ними сетевые соединения.  

systemctl  
// Основной инструмент управления службами (демонами) в системах с systemd.  
// Позволяет запускать, останавливать, перезапускать службы, а также проверять их статус.  
// Примеры:  
// sudo systemctl status apache2 - показывает статус службы apache2  
// Рабоатет ли журанл последних сообщений.  
// sudo systemctl stop apache2 / start apache2 - остановить/запустить службу;  
// restart - перезапустить службу.  
// enable/disable - включить/выключить АВТОЗАПУСК службы при старте системы.  

journalctl  
// Просмотр логов systemd (журнала).  
// Пример:  
// journalctl -u ngnix -f - покажет сообщения журнала для службы nginx и будет следить  
// за новыми (флаг -f).  
// Используйте -b для логов текущей загрузки, -k для dmesg (сообщений ядра), или комбинаций  
// флагов для фильтрации по времени, приоритету и т.д.  

systemd-analyze  
// Инструмент для диагностики процесса загрузки systemd.  
// Пример:  
// systemd-analyze blame - покажет, сколько времени занял старт каждой службы при последней загрузке;  
// systemd-analyze critical-chain - последовательность  задержек. Полезно для оптимизации старта системы.

5. Права доступа, sudo, брандмауэр, безопасность и разрешения.  

chmod  
// Изменения прав доступа (change mod).  
// Права в Linux выражаются для владельца/группы/всех остальных в виде комбинации:  
// ЧТЕНИЕ(R), ЗАПИСЬ(W), ВЫПОЛНЕНИЕ(X).  

// Буквенные примеры:  

// chmod u+rw <файл> — добавить владельцу (u) права на чтение (r) и запись (w).  
// chmod u+x <имя_файла> — добавить право выполнения только для владельца (user).  
// chmod +x <имя_файла> — добавить право выполнения для всех (аналог a+x — all).  
// chmod -x <имя_файла> — убрать право выполнения.  
// chmod a-w <файл> — убрать право записи (w) для всех (a).  
// chmod -R 755 <каталог> — применить права рекурсивно (-R) ко всем файлам и папкам внутри указанного каталога.  

// Числовые примеры:  

// chmod 1777 <каталог> — включает Sticky bit (папка вроде /tmp: писать могут все,  
// но удалять или переименовывать — только владелец файла).  

// chmod 777 <файл_или_каталог> — полный доступ для всех (чтение, запись, выполнение).  
// Использовать с осторожностью — это небезопасно.  

// chmod 755 <файл_или_каталог> — полный доступ для владельца, чтение и  
// выполнение для группы и остальных (стандарт для скриптов, программ и папок).  

// chmod 700 <каталог> — полный доступ только для владельца; группа и остальные  
// не имеют доступа (стандарт для домашних каталогов и папки ~/.ssh).  

// chmod 644 <файл> — чтение и запись для владельца, только чтение для группы  
// и остальных (стандарт для обычных файлов и веб-страниц).  

// chmod 600 <файл> — чтение и запись только для владельца (стандарт для приватных SSH-ключей id_rsa).  

// Остальные примеры:  

// chmod 600 file - установит права rw——- (только владелец может читать/писать) для file.  
// chmod -R u+rX,g-rwx,o-rwx /srv рекурсивно выдаст владельцу право чтения и выполнения на файлы/папки  
// в /srv, убрав все права для группы и остальных.  

chown  
// Смена владельца файла/директории.  
// Пример:  
// chown <новый_владелец>:<новая_группа> файл.  
// sudo chown user:users notes.txt сделает user новым владельцем файла notes.txt и назначит группу users.  
// Флаг R выполняет операцию рекурсивно для папок.  

chmod vs. chown  
// Первая меняет права, вторая - владельца.  
// Проверить текущие права и владельцев можно командой ls -l  

sudo  
// [S]uper [U]ser [DO]  
// Выполнение команды с правами суперпользователя (админа/root-a).  
// Требует ввода пароля текущего пользователя (если он в sudoers).  
// Пример:  
// sudo nano /etc/hosts - откроет файл hosts от имени администратора, т.е. позволит сохранить изменения.  
// Для получения root-оболочки можно использовать команду: sudo su, или sudo -i  

su  
// Смена пользователя, [S]witch [U]ser.  
// Вызов su без аргументов переключит на root-a (нужен будет пароль).  
// После su окружение изменится на новое (в т.ч. домашняя директория).  
// Выйти из сессии su можно командой exit, или сочетанием клавиш Ctrl + D.  

passwd  
// Смена пароля пользователя.  
// Пример:  
// passwd (без параметров) запросит ввод нового пароля для текущего пользователя.  
// Администратор может менять пароли других, например:  
// sudo passwd username задаст новый пароль для username.  
// Команда также используется для блокировки учётки:  
// passwd -l username (lock) и разблокировки:  
// passwd -u username (unlcok).  

umask  
// Устанавливает маску создания файлов (какие права не будут выставлены по умолчанию при создании новых файлов и папок).  
// Пример:  
// umask 077 - новые файлы будут доступны только владельцу (никаких прав для группы и других).  
// Текущую маску можно посмотреть просто командой umask.  

ufw  
// Простой firewall. В Убунту зачастую поставляется из коробки.  
// Посмотреть, есть он или нет можно командой sudo ufw status.  
// Если его нет, устанавливается вот так:  
// sudo apt update  
// sudo apt install ufw  
// sudo ufw enable  
// Чтобы открыть 22/SSH: sudo ufw allow 22/tcp  
// Чтобы закрыть 22/SSH: sudo ufw deny 22/tcp  
// Чтобы посмотреть текущие правила: sudo ufw status  
// Чтобы перезагрузить правила: sudo ufw reload  
// Чтобы выключить ufw: sudo ufw disable  

iptables  
// Утилита для настройки брандмауэра на низком уровне (в ядре Линукс).  
// Очень мощная, но требует понимания.  

// Обычно, iptables доступен из коробки. Проверить можно так: iptables --version  
// Устанавливается так:  
// sudo apt update  
// sudo apt install iptables  

// Пример:  
// sudo iptables -L -n -v - покажет текущие правила фильтрации.  
// sudo iptables -t nat -L -n -v - покажет правила NAT.  
// Пример создания правила:  
// sudo iptables -A INPUT -p tcp -dport 80 -j ACCEPT - разрешит входящие соединения на 80 порт.  

fail2ban  
// Инструмент для защиты от перебора паролей (брутфорса).  
// Мониторит логи выбранных сервисов (ssh, ftp и др.) и при большом числе неудачных попыток или подозрительной  
// активности банит IP нарушителя через правила фаерволла на заданное время.  
// Пример:  
// после установки, выполняем sudo fail2ban-client status чтобы увидеть активные "тюрьмы" (jails)  
// и количество заблокированных IP.  
// sudo fail2ban-client status sshd покажет статистику по jail для SSH.  
// Параметры фильтров настраиваются в /etc/fail2ban/jail.local (количество попыток, время бана и т.д.)
